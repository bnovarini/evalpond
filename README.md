## What is this, and why should you care?

You have probably seen an AI feature that worked in the demo and then got things wrong in real use. The usual reason is that nobody measured how often it is right. An **eval** is how you measure that: write a fixed set of test questions with known right answers, run the AI on all of them, score every answer, and look at the totals. Change the prompt or the model, run it again, and you can see whether the change helped, hurt, or did nothing.

Running one end to end teaches you things that are hard to learn from reading. How many test cases it takes before a result means anything. Why two runs of the same model score differently. What "no clear difference" looks like, and why most small improvements are exactly that. How to tell a model that is wrong from a test that is badly written. evalpond lets you do this in about ten minutes, with no API key, on fake data, and shows the results in a report written in plain words.

**Who this is for:** product managers and others who work with AI features and want to understand the eval loop well enough to ask good questions and read results critically. **Who it is not for:** engineers who need production eval tooling. This is a small teaching harness with 100 synthetic tasks, not a platform for CI gates, large datasets or monitoring. Tools like that exist and are better at it.

**Try it now, no install:** [open the Colab notebook](https://colab.research.google.com/github/bnovarini/evalpond/blob/main/notebooks/evalpond_quickstart.ipynb), run all cells, and read the report. Or look at a finished example: [sample report](https://bnovarini.github.io/evalpond/) and [PRD summary report](https://bnovarini.github.io/evalpond/prd/). Both use scripted stand-in models, not real AI.

**A small tool that shows product managers how evals work.** It runs a fixed set of tasks against an AI model, grades every answer, and produces a report that says, in plain words, whether a change made things better or worse.

evalpond is a small harness for learning how eval loops work. It is not a production eval platform.

> **Status: working, still being polished.** The task generator, graders, runner, statistics, report and a no-keys quickstart all work and are tested. Real-model runs (Anthropic, OpenAI, any OpenAI-compatible endpoint) are implemented but have not been run against live APIs yet, so treat them as untested until the first sample run is committed.

## What is an eval?

An eval is a unit test for AI behavior you cannot check with `output == expected`. You write a set of tasks, decide how each answer gets scored, and run the set every time something changes: a new model, a new prompt, a new tool. Without that, every prompt tweak is a guess: three cases get better, two quietly get worse, and you ship anyway.

## What this project gives you

- A demo task set about **reading synthetic proof-of-income documents** (pay stubs and bank statements): pulling out fields, calculating monthly income, checking a package is complete, and spotting documents that contradict themselves.
- Three ways of grading, from most to least trustworthy: exact match, rubric, and AI-as-judge.
- A report that explains itself. Every number comes with a one-line plain explanation, and every comparison ends with a verdict like "no clear difference" instead of a bare p-value.
- A way to run it all with **no API keys**, using a scripted mock model, so you can see the whole loop in about 10 minutes.

## Tool, not a course

This is a working tool with a good report and one short guide. It is not a tutorial site. There are no lessons or quizzes by design.

## Quick start (about 10 minutes, no API keys)

You need Python 3.11+ and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/bnovarini/evalpond && cd evalpond
uv sync
uv run evalpond quickstart
```

That generates 60 fake income documents, has three scripted stand-in models answer them, grades every answer, and opens a report. The stand-ins are fake on purpose, so it costs nothing. In the report, compare `mock-weak` with `mock-strong` (a clear improvement), then `mock-strong` with `mock-strong-b` (no clear difference, which is the lesson).

Other commands: `evalpond gen` (make the task set), `evalpond run --model NAME` (run one model), `evalpond compare RUN_A RUN_B`, `evalpond report`, `evalpond calibrate` (check the AI grader against your own judgment). Models live in `models.yaml`; API keys come from environment variables, never from the repo.

## Second task pack: summarizing PRDs

The first pack reads income documents. The second one tests something every PM has seen: a model summarizing a product requirements document (PRD).

```bash
uv run evalpond gen --pack prd
uv run evalpond run --model mock-strong --taskset tasksets/prd_v1 --out runs-prd
uv run evalpond report runs-prd --taskset tasksets/prd_v1 --out site-prd
```

40 synthetic PRDs for made-up products. Each summary is checked for the goals, the success metric and its current target, what is out of scope, and the key requirements. It is also checked for made-up content: numbers that are not in the document, a dropped idea presented as the plan, an old target that a changelog replaced. Ten tasks have a missing section, and the right answer says "not stated" instead of guessing. All checks are plain key-phrase and number checks, so no AI grader is needed. See [docs/PRD_PACK.md](docs/PRD_PACK.md).

## Using it for your own tasks

The harness does not care about income documents. Any task set in the same simple format (input, expected answer, how to grade) works. Income documents are the demo set.
